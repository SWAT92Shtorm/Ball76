## ⚙️ Как это работает

```
Браузер ──HTTPS──► nginx (443) ──┬── /            → статика (index.html, app.js, styles.css)
                                 │
                                 └── /api/*        → Node-контейнер (127.0.0.1:8080)
                                                          │
                                                          └──► PostgreSQL (только внутренняя сеть)
```

- **Один домен** для страницы и API — [`app.js`](app.js:98) берёт адрес API как `location.origin`, CORS не нужен.
- **Конфиг (залы, цены, телефоны, расписание)** живёт в [`server.js`](server.js:209) (`APP_CONFIG`) и отдаётся клиенту через `GET /api/config`. Дублировать его в `index.html`/`app.js` не нужно.

## 🗄️ База данных

**Таблицы:**

| Таблица | Сущность | Связь |
|---------|----------|-------|
| `players` | Игроки (ФИО, уникальное) | 1 игрок → много записей |
| `games` | Игры (зал + дата) | 1 игра → много записей |
| `game_players` | Записи | PK `(game_id, player_id)` — защита от дублей |

**Правила игры:**
- Максимум **18** игроков на игру ([`server.js`](server.js:217))
- Минимум **10** человек для игры
- Даты в формате `YYYY-MM-DD` (московское время)

**Доступ к БД:**
- В облаке: `DATABASE_URL=postgres://Ball76:<пароль>@db:5432/Ball76`, пароль в `/opt/ball76/.env`
- Локально: `postgres://Ball76:Ball76@localhost:5432/Ball76`

### 🏢 Управление залами (Кабинет ответственного)

Залы и их график теперь **не зашиты в код** — они хранятся в таблице `halls`
и редактируются прямо на сайте:

1. Вход админа (пароль): кнопка **«Настройки»** в верхней информационной панели
   администратора, либо долгое нажатие (~1.5 с) на версию в футере.
   Открывается **«Кабинет ответственного»**.
2. Вкладка **«🏢 Залы»** → список залов, кнопка **«➕ Добавить зал»**.
3. В форме задаются: название, телефон, ответственный, **цена за час**,
   сумма с человека и **график** (дни недели + часы). Цены за 1,5 ч и 2 ч
   считаются автоматически (×1.5 и ×2) и показываются под полем ввода.
   Системное имя (`hallN`) админ не вводит — сервер генерирует его сам
   по подобию существующих.
4. **Удаление:** если по залу уже есть игры — он не удаляется, а **скрывается**
   (деактивируется), история сохраняется. Системное имя зала с играми менять нельзя.

Таблица создаётся автоматически при старте сервера (миграция
[`003_halls.sql`](migrations/003_halls.sql:1)); существующие залы `hall1`/`hall2`
переносятся из старого конфига. Бот и сайт получают залы через `GET /api/config`
в прежнем формате, поэтому дополнительных правок не требуют.

**Защита:** rate-limit — 10 мутаций/мин и 120 чтений/мин с одного IP ([`server.js`](server.js:69)).

### ✅ Подтверждение игры (Кабинет ответственного)

Длительность игры задаётся **только здесь** (поле «Длительность» в Кабинете ответственного):
на главной странице игрок её больше не выбирает, а стоимость аренды и сумма на
человека рассчитываются по времени начала/конца, выставленному админом.

Во вкладке **«🕒 Время игры»** рядом с полем «Длительность» есть кнопка
подтверждения игры:

1. Изначально кнопка **красная** («Подтвердить игру»).
2. По нажатию игра помечается подтверждённой — кнопка становится **зелёной**
   («✅ Игра подтверждена — N ₽/чел.»). Действие **обратимо** (повторный клик снимает).
3. Состояние хранится в БД по паре **зал + дата**, поэтому сохраняется после
   перезагрузки страницы и повторного входа.
4. В **«Истории записей»** у подтверждённой игры показываются три маркера
   одного размера в порядке **Время → Количество → Стоимость**:
   длительность («2 часа» / «1 час 30 мин»), число участников («12 чел.»)
   и сумма к оплате на человека («500 ₽/чел.»). Иконки не используются,
   знак «₽» идёт после суммы.

Сумма на человека фиксируется в момент подтверждения: если у зала задана
фиксированная сумма (`perPerson`) — берётся она, иначе цена аренды за
подтверждённую длительность делится на число записавшихся (в пределах лимита 18).
При изменении времени или состава участников подтверждённой игры снимок
пересчитывается автоматически.

Поля хранятся в таблице `games` (миграция
[`005_game_confirmation.sql`](migrations/005_game_confirmation.sql:1)):
`confirmed`, `confirmed_at`, `confirmed_price`, `confirmed_players`,
`confirmed_duration` (длительность в часах на момент подтверждения).

## 🖥️ Подключение к базе данных

Порт Postgres **не открыт в интернет** — он слушает только `127.0.0.1` на сервере. Снаружи БД доступна только двумя безопасными способами.

### Способ 1. На сервере (быстро глянуть данные)
```bash
ssh ball76
docker exec -it ball76-db psql -U Ball76 -d Ball76
# \dt  — таблицы;  \q — выход
```
Одной командой:
```bash
ssh ball76 'docker exec ball76-db psql -U Ball76 -d Ball76 -c "SELECT COUNT(*) FROM players"'
```

### Способ 2. SSH-туннель с Mac → GUI-клиент (DBeaver, pgAdmin, TablePlus)
Туннель живёт, **пока открыт терминал** (или пока не остановите). Закрыли окно — туннель пропал; при необходимости запустить снова.

**Foreground** (видит окно, Ctrl+C — стоп):
```bash
ssh -i ~/.ssh/id-ball76 -N -L 5433:127.0.0.1:5432 root@31.56.211.5
```

**В фоне** (терминал освобождается):
```bash
ssh -i ~/.ssh/id-ball76 -N -f -L 5433:127.0.0.1:5432 root@31.56.211.5
# остановить:
pkill -f "5433:127.0.0.1:5432"
```

**Параметры подключения в клиенте:**

| Поле | Значение |
|------|----------|
| Host | `127.0.0.1` |
| Port | `5433` |
| Database | `Ball76` |
| User | `Ball76` |
| Password | из `/opt/ball76/.env` (переменная `POSTGRES_PASSWORD`) |

Узнать пароль: `ssh ball76 'cat /opt/ball76/.env'`

## 🌍 Домен и HTTPS

### Что используется

| Параметр | Значение |
|----------|----------|
| Домен | **`ball76.duckdns.org`** |
| Тип | Бесплатный поддомен **DuckDNS** (динамический DNS) |
| Куда ведёт | A-запись → `31.56.211.5` (IP сервера) |
| Сертификат | Let's Encrypt, `CN=ball76.duckdns.org`, действует до **2026-12-27** |
| Обновление | автоматически, `certbot.timer` (dry-run проверен) |
| Редирект | `http://` → `https://` (301) |

### Почему именно так

- **Свой домен (`.ru`) стоит денег** (~300–900 ₽/год), а полноценный бесплатный не выдаётся.
- **DuckDNS** даёт бесплатный поддомен `имя.duckdns.org`. Соответствие «имя → IP» хранится в аккаунте DuckDNS, поэтому имя может быть любым (`ball76`).
- **Сертификат нужен именно на домен:** Let's Encrypt **не выдаёт сертификаты на IP-адреса**, только на DNS-имена. Поэтому домен — обязательное условие для HTTPS.
- **HTTPS закрывает передачу ФИО игроков** открытым текстом и убирает «Не защищено» в браузере.

### Альтернативы (если понадобится)

| Вариант | Имя | Регистрация |
|---------|-----|-------------|
| **DuckDNS** (используется) | `ball76.duckdns.org` | 1 минута через GitHub |
| nip.io | `ball76.31.56.211.5.nip.io` | не нужна, IP внутри имени |
| sslip.io | `ball76.31.56.211.5.sslip.io` | не нужна, IP внутри имени |
| eu.org | `ball76.eu.org` | ручная модерация (дни–недели) |
| свой `.ru` | `ball76.ru` | платно |

> ⚠️ `ball76.nip.io` **не сработает** — nip.io определяет IP из имени, и без IP в имени вернёт localhost.

### Управление доменом

**Сменить IP (если сервер переедет):**
1. Зайти на **duckdns.org** (вход через GitHub).
2. В строке `ball76` поле **current ip** → новый IP → **update ip**.

**Перевыпустить сертификат вручную:**
```bash
ssh ball76 'certbot --nginx -d ball76.duckdns.org'
```

**Проверить, что домен указывает на сервер:**
```bash
nslookup ball76.duckdns.org 8.8.8.8
# должно вернуть 31.56.211.5
```

**Проверить статус и срок сертификата:**
```bash
ssh ball76 'certbot certificates'
```

### Как домен привязан в коде

| Файл | Что изменено |
|------|--------------|
| [`index.html`](index.html:9) | canonical, og:url, og:image → `https://ball76.duckdns.org/` |

| [`sitemap.xml`](sitemap.xml:4) | `<loc>` → `https://ball76.duckdns.org/` |

> В [`app.js`](app.js:98) домен **не прописан жёстко** — берётся текущий origin. Поэтому смена домена не требует правок в коде.

## 🧹 Кэш браузера и версионирование фронтенда

Чтобы правки `app.js`/`styles.css` подхватывались сразу, на сервере настроено:

- **HTML (`index.html`) — не кэшируется:** `Cache-Control: no-cache, must-revalidate`.
- **JS/CSS — кэш 7 дней, но с версией в URL:** [`index.html`](index.html:147) подключает `app.js?v=20260928prod`. Картинки — 30 дней.

**Правило:** после каждой правки `app.js` или `styles.css` меняйте `?v=...` в [`index.html`](index.html:147) на новую метку (например `?v=20260929`). Иначе браузеры пользователей до 7 дней будут отдавать старую версию из кэша.

### Если у пользователя ошибка «Fetch is aborted» / «API недоступен»
Это старая версия `app.js`, застрявшая в кэше, либо старый адрес туннеля в `localStorage`. Решение:

```js
// в консоли браузера (F12): очистить старый адрес API и перезагрузить
localStorage.removeItem('ball76_api'); location.reload(true);
```

Либо жёсткая перезагрузка: `Cmd+Shift+R`. На боевом домене `app.js` теперь **всегда** берёт `location.origin` и очищает `localStorage['ball76_api']` — старые туннели loca.lt больше не могут сломать сайт.
